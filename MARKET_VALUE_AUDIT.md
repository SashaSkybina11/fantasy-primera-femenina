## Backend и Prisma

`backend/src/services/player-prices.ts` уже реализует требуемые величины: гол +100, реальный старт +30, жёлтая −15, красная −30. События суммируются: указанные комбинации дают +215 и +65.

Для вратаря: 0 пропущенных +50, 1 — 0, далее −10 за каждый пропущенный сверх первого. Существующее поведение сохранено: 5 → −40, 6 → −50. Неуказанная статистика пропущенных (`null`) даёт 0 по этому компоненту. Цена 0 или ниже отклоняется с откатом транзакции.

Бонус `PriceSettings.teamWin` удалён из бизнес-логики по последующему запросу. Победа, ничья и поражение не влияют на изменение цены. Настройка, API и элементы админки удалены; старые поля БД сохранены без разрушительной миграции. Подробности — в `TEAM_WIN_REMOVAL_REPORT.md`.

`previewPlayerPrices` берёт статистику реального тура для всех игроков, независимо от владения и Fantasy-статуса. `applyPlayerPrices` обновляет глобальный Player.price. `recalculateGameweek` считает пользовательские очки только по STARTER в сохранённом составе тура. Реальный `started` и Fantasy STARTER — разные признаки.

История существует: PlayerPriceChange с уникальным ограничением `(playerId, gameweekId)`. Повторный расчёт заменяет запись, не прибавляет всю сумму заново. Коррекция раннего тура пересчитывает последующие записи и итоговую цену. Устаревший preview отклоняется по revision. Применение цен и пересчёты администратора выполняются в serializable-транзакциях с повтором при конфликте.

## Покупка, продажа и отображение

`backend/src/routes/team.ts`: покупка списывает актуальный Player.price, продажа прибавляет `entry.player.price`, прочитанный внутри транзакции. История UserTransfer фиксирует цену операции. Историческая цена покупки при продаже не используется.

Особенность существующей истории: до завершения первоначального набора состава покупки и продажи не записываются в UserTransfer. Это связано с исключением первоначального набора из трансферного лимита. Полный журнал первоначальных операций не добавлялся, чтобы не изменить ограничения трансферов.

Каталог `/players`, `/player-prices`, клубные списки и `/my-team` читают один Player.price. Frontend использует эти значения. После применения цен инвалидируются запросы; проверка обновления после изменения статистики проходит. Другие открытые браузеры обновляются опросом (по умолчанию 30 секунд), а не мгновенным push-событием. Продажа всегда использует свежую серверную цену.

Интеграционный сценарий: бюджет 50000 → покупка за 2000 → 48000 → гол запасной → цена 2100 → повторный расчёт остаётся 2100 → продажа → бюджет 50100. UserTransfer содержит BUY 2000 и SELL 2100. Отдельно подтверждено отсутствие начисления Fantasy-очков за гол запасной.
