# Fantasy Primera División Fútbol Sala Femenino

Fantasy-игра для женской испанской футзальной Primera División. Это монорепозиторий с React/Vite-клиентом, Express API и PostgreSQL через Prisma.

## Локальный запуск

Требуются Node.js 20+, npm 10+ и PostgreSQL 15+.

```powershell
npm install
Copy-Item .env.example .env
Copy-Item .env.example backend/.env
Copy-Item frontend/.env.example frontend/.env
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

В `backend/.env` укажите `DATABASE_URL` для PostgreSQL и длинный случайный `JWT_SECRET`. Клиент в режиме разработки открывается на `http://localhost:5173`; API — на `http://localhost:4000`.

## Проверенные игровые правила

- У каждой участницы создаётся своя команда и бюджет €50 000.
- Страница «Моя команда» показывает только действительно купленных игроків; пустой состав не заполняется карточками-заглушками.
- Рынок проверяет бюджет, дубликаты, максимум 10 игроков и максимум 2 игрока из одного реального клуба. Последнее правило проверяется сервером в сериализуемой транзакции, поэтому его нельзя обойти запросом к API.
- При продаже игрока его стоимость возвращается в бюджет, и игрок исчезает из состава.
- Изменения состава, профиля, регистрация и авторизация сохраняются в PostgreSQL, поэтому доступны нескольким пользователям одновременно.
- Каждая участница может выбрать любимый реальный клуб; на странице «Лига» виден общий рейтинг поддержки клубов.

## Очистка пользователей

Чтобы начать тестирование заново, не удаляя клубы, игроков и лигу, выполните в PowerShell из корня проекта:

```powershell
$env:CONFIRM_DELETE_USERS="YES"
npm run db:clear-users
```

Команда удаляет только пользовательские аккаунты и связанные fantasy-команды. Защита `CONFIRM_DELETE_USERS=YES` обязательна, чтобы случайный запуск не очистил данные. Для очистки production-базы запускайте эту команду только после временной установки её `DATABASE_URL` в окружении, а не из обычного Vercel-деплоя.

## Деплой на Vercel

Проект подготовлен для единого Vercel-деплоя: Vite отдаёт статический интерфейс, а `api/[...path].ts` запускает существующий Express API как serverless-функцию на том же домене. В production клиент использует относительный `/api`, а не `localhost`.

1. Создайте удалённую PostgreSQL базу (например, через Vercel Marketplace / Neon или другой совместимый провайдер). Не используйте локальную БД.
2. В Vercel импортируйте репозиторий, выберите корневую папку проекта и оставьте настройки из [`vercel.json`](./vercel.json). Не задавайте `VITE_API_URL`: API будет работать на том же публичном домене.
3. В Project Settings → Environment Variables добавьте для Production (и Preview, если нужны preview-сборки):

   | Переменная | Значение |
   | --- | --- |
   | `DATABASE_URL` | строка подключения к удалённой PostgreSQL с SSL, выданная провайдером |
   | `JWT_SECRET` | новый случайный секрет длиной не менее 32 символов |
   | `FRONTEND_URL` | публичный URL Vercel-проекта, например `https://your-project.vercel.app` |
   | `BLOB_READ_WRITE_TOKEN` | токен Vercel Blob; нужен, чтобы загруженные аватары сохранялись после serverless-вызовов |

4. В разделе Storage создайте и подключите Vercel Blob. Vercel может добавить `BLOB_READ_WRITE_TOKEN` автоматически; если нет, добавьте его вручную. Без этой переменной сама игра продолжит работать, но загрузка нового аватара в production корректно вернёт понятную ошибку вместо сохранения файла во временную файловую систему.
5. Нажмите Deploy. Команда `vercel-build` генерирует Prisma Client, применяет миграции, выполняет идемпотентный seed клубов/игроков и собирает обе части приложения. После первого успешного деплоя используйте URL, показанный Vercel, — он уже подходит для телефонов и компьютеров.

Не помещайте пароли, `JWT_SECRET`, URL базы с учётными данными или Blob-токены в git и не добавляйте их в `VITE_*`: такие переменные становятся видны браузеру.

## Команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Запуск frontend и API локально |
| `npm run build` | TypeScript-проверка и production-сборка |
| `npm run db:generate` | Генерация Prisma Client |
| `npm run db:migrate` | Применение миграций локально |
| `npm run db:seed` | Идемпотентная загрузка клубов, игроков и лиги |
| `npm run db:clear-users` | Удаление всех пользователей после явного подтверждения |
| `npm run vercel-build` | Production-команда, используемая Vercel |
